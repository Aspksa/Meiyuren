# Meiyuren v0.6: диагностика Cloud.ru, SSE и SQLite

## Диагностика

`GET /api/cloud/diagnostics` проверяет наличие ключа, доступность `GET /v1/models`, наличие выбранного ID в списке и примерную задержку. Этот вызов **не запускает генерацию и не подтверждает, что модель примет конкретный запрос**.

Тестовый вызов выполняется отдельно после подтверждения пользователя. Это обычное сообщение в основном диалоге, и **он может быть платным**. API-ключ не возвращается из backend.

## Потоковые ответы

`POST /api/chat/stream` принимает JSON `{text,requestId,conversationId}`. Браузер подключается по `fetch` и обрабатывает события SSE `delta`, `done`, `error`. Backend передаёт `stream: true` в Cloud.ru, буферизация отключена.

`done` означает, что ответ уже записан в SQLite. При отмене/обрыве поток маркируется как **неизвестный результат**, ответ и запрос могут не появиться в истории. Cloud.ru всё равно мог вычислить токены или завершить генерацию. Повтор с тем же ID заблокирован; новый запрос требует предупреждения о стоимости. Сервер не способен гарантировать отмену уже выполняемой генерации у провайдера.

## Диалоги и память

- Основной диалог `main` сохраняет историю прежних версий; дополнительные диалоги создаются с UUID.
- Таблица `memory_facts`: только факты, сохранённые пользователем самостоятельно; не происходит автоматического извлечения из переписки.
- Поиск использует параметризованный SQLite LIKE, работает по локальной истории. Экспорт и синхронизация пока отсутствуют.
- Данные сохраняются в `data/meiyuren.sqlite3` рядом с приложением, не отправляются в Cloud.ru кроме контекста при включённом облаке.

## Тестирование

Тесты мокируют Cloud.ru, не отправляют реальные данные и не создают расходов. Windows CI использует CMD, Linux — Bash. Режим Cloud.ru требует ключ, сохранённый локально в системном хранилище.
