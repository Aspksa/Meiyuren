# Cloud.ru в Meiyuren

## Настройка

В Meiyuren v0.5 открывайте слева значок облака (SVG, без текстовой подписи). Введите API-ключ Cloud.ru Foundation Models (именно Key Secret), сохраните, загрузите список моделей и выберите **текстовую LLM**. Нажмите «Применить модель», чтобы включить облачный режим для чата. Для отключения нажмите «Выключить Cloud.ru».

API согласно [официальной спецификации Cloud.ru](https://cloud.ru/docs/foundation-models/ug/topics/api-ref__specs):
- `GET https://foundation-models.api.cloud.ru/v1/models`
- `POST https://foundation-models.api.cloud.ru/v1/chat/completions`

Авторизация: Bearer API key. Адрес жёстко задан на сервере: пользователь не может подменить API-endpoint через настройки.

## Где хранится ключ?

Только в системном keyring текущего пользователя ОС (например, Credential Manager на Windows). Не в localStorage, не в SQLite и не в репозитории. Сервер не имеет маршрута для просмотра секрета. Если надёжное системное хранилище недоступно, запись ключа блокируется.

**Важно:** это не средство защиты от вредоносных процессов, выполняющихся с правами той же учётной записи. Не публикуйте порт Python в сеть; локальный API не рассчитан на многопользовательский сервер.

## Расходы и приватность

При включённом облаке отправляются текст запроса, до 12 последних реплик, сохранённая заметка памяти (если есть). Cloud.ru может взимать плату за токены, и данные обрабатываются провайдером. В демо-режиме запросы наружу не отправляются.

## Проблемы подключения

- `401/403`: проверьте API-ключ, разрешения сервисного аккаунта и срок действия.
- `429`: превышение лимита, попробуйте позже.
- Пустой список: нет доступных моделей, уточните права сервисного аккаунта.
- Хранилище секретов не работает: проверьте Windows Credential Manager или установленный keyring-бэкенд.

## Как обновить окружение на Windows

```cmd
git pull origin main
npm ci
setup-python.cmd
```

Затем запустите `Meiyuren.cmd`. PowerShell не используется.

## Результаты аудита стабильности (v0.5.x)

- Лимит ответа модели увеличен с 450 до 1200 токенов. Если Cloud.ru вернёт `finish_reason: length`, пользователь увидит отметку об обрезанном ответе.
- Контекст последних сообщений ограничен 6500 символами, заметка памяти — 1800 символами на запрос (полная заметка продолжает храниться локально). Это приблизительный бюджет, **не точный подсчёт токенов**: некоторые модели с небольшим окном всё ещё могут отклонять длинный ввод.
- Из списка моделей исключены явно несовместимые embedding/rerank/audio/image-модели. Перед включением новой модели пользователь должен заново загрузить список для текущего API-ключа. Некоторые модели с необычными метаданными всё ещё могут оказаться несовместимыми.
- Ошибки `402` (оплата), `404` (модель недоступна), `429` (лимит) и тайм-ауты теперь сопровождаются более точной подсказкой. В случае `timeout` запрос **мог быть обработан** на стороне Cloud.ru, поэтому не отправляйте его повторно без проверки истории и расходов.
- Контроль дублирования платных операций при потере HTTP-ответа после успешной генерации на сервере **ещё не реализован**. В будущем требуется долговременный идентификатор запроса и журнал статусов, а также учёт неоднозначного результата при сбоях сети.

Ни одна проверка CI не выполняет реальные платные запросы Cloud.ru: используются имитации API и системного хранилища. Для проверки реального доступа нужно использовать собственный ключ внутри локального Meiyuren.

## Повторный полный аудит: ключ, API, база, интерфейс, запуск

- При замене API-ключа прежний облачный режим отключается сервером. Нужно заново запросить список моделей и явно применить модель.
- Все изменяющие запросы локального API требуют заголовок `X-Meiyuren-Client: 1`; для мутаций настроек Cloud.ru дополнительно требуется совпадающий `Origin`. Прямое обращение к FastAPI разрешено лишь на `127.0.0.1`. Это **не аутентификация локального пользователя** и не защита от другого процесса под той же учётной записью.
- Backend теперь проверяет наличие `fastapi`, `uvicorn`, `httpx` и `keyring` перед стартом; при неполной установке нужно снова вызвать `setup-python.cmd`.
- При включённом Cloud.ru браузер отправляет уникальный `requestId`. До внешнего вызова он резервируется в SQLite (`cloud_requests`). Повтор с тем же ID после успешного запроса возвращает сохранённый ответ, не вызывая Cloud.ru повторно. Если результат неизвестен, повтор с тем же ID блокируется.
- Для **нового** запроса после неясного результата нужен осознанный выбор пользователя: в чате показано предупреждение о возможной повторной оплате. Текст можно изменить и отправить как новый запрос. Перезапуск вкладки и отправка вручную нового сообщения создают новый ID; это не гарантирует дедупликацию на стороне Cloud.ru.
- Сервер резервирует ID перед запросом, а успешный ответ записывает атомарно с отметкой о завершении. Однако при аварии после обработки запроса Cloud.ru, но до записи результата сервер не способен восстановить ответ от провайдера; ID останется заблокированным для безопасного повтора.
- Ошибки некорректного формата ключа не содержат исходное значение в теле ответа API.
- Регрессионные тесты покрывают смену ключа, авторизацию локальных изменений, обработку ошибок, резервирование и повторные запросы после перезапуска.

**Ограничения:** приложение по-прежнему не проверяет реально начисленную стоимость Cloud.ru, доступность конкретной модели на стороне аккаунта и ответ провайдера через живое подключение без персонального ключа. Параметр `max_tokens` используется по примеру официального быстрого старта Cloud.ru; OpenAPI-спецификация также документирует `max_completion_tokens`. Если конкретная модель отклоняет параметры, требуется проверка её индивидуальных требований.

Внимание: при включении облака последние сообщения и часть заметки памяти передаются в Cloud.ru. Содержимое заметки следует считать пользовательскими данными, а не доверенными командами для агента.
