# Meiyuren v0.10 — восемь связанных областей долговременной памяти

Веб-аватар Meiyuren (React + TypeScript + Vite), левое SVG-меню, обновления GitHub и локальный сервер Python/FastAPI.

## Первый запуск на Windows (только CMD, без PowerShell)

После обновления Git-копии проекта:

```cmd
git pull origin main
npm ci
```

Дважды нажмите `setup-python.cmd`: скрипт создаст `backend/.venv` и установит FastAPI/Uvicorn (нужен Python 3.11+ и интернет для первой установки). Затем двойной щелчок по `Meiyuren.cmd` — Node найдёт свободные порты для сайта и Python, запустит оба сервера и откроет браузер.

Команды для обычной CMD вместо двойного щелчка:

```cmd
setup-python.cmd
npm run dev
```

На Linux/macOS:

```bash
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.txt
npm ci
npm run dev
```

При переносе папки на другой компьютер или носитель Python-окружение `backend/.venv` иногда нужно пересоздать. База `data/meiyuren.sqlite3` не включена в Git и остаётся с проектом.

## Чат

- История сообщений сохраняется в SQLite и отображается после перезапуска.
- Отправка сообщения записывает пару «вопрос/ответ» одной транзакцией.
- Окно показывает загрузку истории, состояние ответа и ошибки соединения.
- Очистка истории доступна из настроек после подтверждения.

## Память

В настройках → «Память Мэйюрэн» можно вручную записать и сохранить заметку (не более 4000 символов). Она остаётся в SQLite, даже если приложение закрыто. Для проверки отправьте в чат «Что ты помнишь?».

**По умолчанию:** демонстрационный локальный бот. Для настоящей облачной модели настройте Cloud.ru в боковом меню (значок облака).

## API

- `GET /api/health` — статус Python.
- `GET /api/chat/messages?limit=200` — последние сообщения.
- `POST /api/chat/messages` — сообщение и ответ.
- `DELETE /api/chat/messages` — удаление истории.
- `GET /api/memory` — чтение заметки.
- `PUT /api/memory` — сохранение заметки.

Python слушает только `127.0.0.1`, порт 8000–8099. Веб-адрес — свободный порт 5173–5272. Vite направляет запросы чата на фактический порт Python.

## Правила

PowerShell не используется. В демо-режиме история и заметки локальные. При включённом Cloud.ru часть истории, текущий запрос и заметка отправляются облачному провайдеру. Не публикуйте локальные API наружу без авторизации. Отдельно сохраняйте резервную копию каталога `data`: Git-откат кода не откатывает пользовательскую базу.

## Cloud.ru Foundation Models (v0.5)

В левом меню появилась новая **векторная иконка облака без подписи** (подсказка при наведении). После клика откроется окно настроек Cloud.ru.

1. Создайте сервисный API-ключ в [консоли Cloud.ru](https://cloud.ru/docs/foundation-models/ug/topics/quickstart) для сервиса Foundation Models.
2. Введите **Key Secret** в поле с маскировкой и нажмите **Сохранить ключ**.
3. Нажмите **Получить список** — сервер проверит подключение через `GET /v1/models`.
4. Выберите текстовую модель и нажмите **Применить модель**. С этого момента чат использует `POST /v1/chat/completions`.
5. Кнопка **Выключить Cloud.ru** возвращает демонстрационный локальный режим. **Удалить** удаляет ключ из системного хранилища.

**Ключ не хранится в браузере, SQLite, Git или файлах конфигурации.** Backend использует библиотеку `keyring` и системное хранилище секретов, например Windows Credential Manager. На ОС без доступного безопасного хранилища сохранение будет запрещено. Секрет никогда не возвращается в ответы API.

Выбранная модель и переключатель облачного режима хранятся в SQLite (`cloud_settings`). Cloud.ru получает **текущий текст, до 12 сообщений истории и содержимое заметки памяти** только при включённом облачном режиме. Запросы могут быть платными, интернет обязателен. Статус ключа доступен без раскрытия его значения.

При обновлении проекта запустите `setup-python.cmd`, чтобы установить новые зависимости Python (`httpx` и `keyring`). Окружение нельзя без проверки переносить между Windows-компьютерами. Повторный вход ключа может потребоваться после переноса на другой ноутбук.

Подробная инструкция: [docs/cloud-ru.md](docs/cloud-ru.md).

## Новое в v0.6: диагностика, поток, память

- **Cloud.ru → Проверить соединение:** проверка ключа и списка моделей через GET /v1/models, без генерации и без расходов на чат. Это не подтверждение работоспособности всех параметров выбранной модели.
- **Cloud.ru → Тест ответа (платно):** после явного подтверждения выполняется короткий реальный запрос; результат записывается в основной чат.
- **Чат:** сообщения Cloud.ru приходят по частям (SSE), доступны остановка ответа, выбор диалога, создание и переименование, удаление второго диалога, поиск по сообщениям.
- **Память:** список фактов, которые пользователь добавляет и удаляет вручную. Существующая заметка остаётся. В облачном режиме ограниченная часть фактов и заметки отправляется Cloud.ru.
- **SQLite:** старые сообщения автоматически закрепляются за «Основным диалогом», новая таблица `conversations`, `memory_facts`, столбец `conversation_id` в `messages` и `cloud_requests`. Изменения мигрируются при запуске.
- **Отмена:** клиент может остановить поток; это не означает, что Cloud.ru не обработал часть запроса или что деньги не списаны. Идентификатор запроса продолжает предотвращать автоматический повтор.

### Потоковое API

`POST /api/chat/stream` — локальный SSE-поток с событиями `delta` (часть текста), `done` (сохранённый обмен), `error`. Поток сохраняется в SQLite только по успешному завершению генерации. Запросы Cloud.ru помечаются `unknown` при прерывании, чтобы повтор с тем же идентификатором не вызвал новый платный запрос.

### Важно при обновлении

**Перед первым запуском новой версии сделайте резервную копию папки `data/`**. Обновление схемы SQLite — изменение данных; откат кода через Git не откатывает структуру базы. Старые сообщения остаются доступными через основной диалог.

Для Windows CMD: `git pull origin main`, `npm ci`, `setup-python.cmd`, `Meiyuren.cmd`.

## Memory Core v0.7: одна локальная система памяти

- Один модуль Python: `backend/app/memory_engine.py` с SQLite, без Ollama, Redis, дополнительного сервиса и дополнительных Cloud.ru вызовов.
- Перед ответом Мэйюрэн ищет актуальные воспоминания через SQLite FTS5 и ограничивает их контекстом. Для Cloud.ru **по умолчанию** передача заметки и фактов запрещена; в настройках нужно явно разрешить категории и конкретный факт.
- После успешного ответа локальная очередь создаёт предложения на сохранение важных фактов (например, «Запомни: ...» и простые предпочтения), а длинным диалогам предлагает **черновики дословных выписок**. Ничего из этого не считается проверенным до подтверждения пользователем.
- Настройки → Память: подтверждение/отклонение кандидатов, редактирование фактов с защитой от конфликтов, источник воспоминания, разрешение передачи Cloud.ru и удаление.
- Для старых фактов отсутствует достоверный источник: они импортируются с меткой `legacy`, без передачи в Cloud.ru.
- Забывание удаляет запись из активного индекса FTS5, старой таблицы, кандидатов и связанных сводок. Оно **не стирает** исходный текст из отдельных сообщений истории и существующих резервных копий.
- Сводки локальные и дословные; НЕ генерируются и НЕ исправляются AI. Автоматического разрешения их отправки в Cloud.ru нет.
- В фоне — только локальная обработка. Никаких автоматических платных запросов Cloud.ru, в том числе после сбоя.

### Перед обновлением

Перед первым запуском v0.7 сделайте дополнительную резервную копию папки `data` при выключенном приложении. При миграции существующей базы Memory Core создаст файл `data/meiyuren.sqlite3.before-memory-core.bak` (однократно, если такого файла нет). Используются резервное копирование SQLite и транзакции.

На Windows только CMD: `git pull origin main`, `npm ci`, `setup-python.cmd`, затем `Meiyuren.cmd`.

### Ограничения

- Локальное извлечение кандидатов использует консервативные правила, а FTS5 — лексический поиск без полноценной русской семантики. Сложные противоречия не разрешаются автоматически, факты не переписываются по предположениям AI.
- Разрешение на передачу памяти **не** запрещает передавать в Cloud.ru последние сообщения активного диалога, если включён облачный чат. Не вводите секреты в облачный чат.
- Локальные резервные копии и прежние Cloud.ru-запросы не отзываются при удалении записи памяти.
- Без отдельного подключения Cloud.ru не проверяется работа с реальным ключом или фактическая тарификация.

## v0.8: надёжность и объяснимость памяти

- **Гонка с Cloud.ru:** очистка истории увеличивает generation диалога в той же SQLite-транзакции. Уже выполняющийся запрос, начатый до очистки, не может снова записать старое сообщение; при неопределённости повтор платного запроса не выполняется.
- **Забывание и сводки:** локальная сводка теперь включает **только подтверждённые и актуальные факты с существующим сообщением-источником**. Сырые реплики не копируются автоматически. Удаление факта удаляет производную сводку, исключает исходный ID и запрещает автоматически переизвлекать его.
- **Очередь:** сводка планируется только после каждых шести обменов (12 сообщений), задания завершённые/ошибочные удаляются из журнала через 7 дней, а выполняемые задания восстанавливаются по lease с ограничением трёх попыток. Отдельных платных Cloud-запросов нет.
- **Версии:** редактирование и подтверждение записываются в локальный журнал ревизий. После удаления факта журнал его содержимого тоже удаляется.
- **Противоречия:** простые противоположные высказывания о предпочтении по одной теме предлагаются на рассмотрение. При подтверждении старое утверждение получает статус superseded и исключается из поиска; сложные противоречия не распознаются автоматически.
- **Поиск:** FTS5 с консервативным усечением типичных русских окончаний, фильтрацией устаревших и запрещённых записей, выводом списка выбранных фактов. Это не семантический поиск.
- **Прозрачность:** в настройках Memory Core можно увидеть происхождение и ревизии факта, срок актуальности, предпросмотр контекста для Cloud.ru и журнал фактов, выбранных при подготовке ответа. Предпросмотр не вызывает генерацию Cloud.ru.
- **Backup:** файл `data/meiyuren.sqlite3.before-memory-core.bak` сохраняется консистентным SQLite-снимком **до** миграции, если файл ещё не существует. Перед обновлением всё равно стоит скопировать всю папку `data` при выключенном приложении.

**Ограничения:** удаление памяти не стирает текст исходных пользовательских сообщений, уже отправленные в Cloud.ru данные или резервные копии; для удаления истории используйте управление диалогами. Журнал выбора памяти означает включение в подготовленный контекст, а не подтверждённый ответ провайдера. Фоновые задачи локальные; Ollama не требуется. Для обновления используйте Windows CMD, не PowerShell.

## v0.9: пять связанных «мозгов» детальной долговременной памяти

Это **пять логических областей одной локальной базы**, а не пять отдельных LLM-процессов:
личность (`identity`), события (`episodes`), цели (`goals`), привычки (`habits`),
знания (`knowledge`). Новые факты распределяются консервативными локальными правилами,
но область можно изменить вручную. Старые факты сохраняются и получают категорию
при миграции (без выдумывания новых сведений). SQLite остаётся единственным хранилищем.

**Нейросвязи** двух видов:

- `shared_topic`: локальный граф связей по пересечению ключевых слов, бесплатно и без сети.
  Одношаговый переход по связям может добавить релевантные факты к FTS5-результатам,
  но не отменяет правила разрешений, области диалога и сроков актуальности.
- `neural_similarity`: настоящие семантические связи по косинусной близости векторов
  embedding-модели `Qwen/Qwen3-Embedding-0.6B` (1024 компоненты).
  Генерация каждого вектора **только вручную**, после разрешения пользователя и
  отдельного подтверждения потенциально платного вызова Cloud.ru.

### Правила приватности и стоимости

По умолчанию `allow_cloud_embeddings=false`. Чтобы индексировать факт нейросетью,
нужно отдельно разрешить embeddings в настройках и разрешить Cloud.ru
**конкретному факту**. Поиск по смыслу тоже требует отдельного подтверждения
и потенциально оплачиваемого API-вызова `POST /v1/embeddings`.
**Никаких фоновых embedding-запросов**, автоматических повторов, Ollama,
Redis или отдельной БД. При сбое результат запроса сохраняется как `unknown`,
повтор того же requestId отклоняется. Ни содержание ключа, ни полные векторы не
возвращаются через API Meiyuren. Нейровекторы и граф хранятся в SQLite.

В настройках памяти доступны распределение по пяти областям, ручное назначение
области факта, просмотр связей, создание вектора, ручной нейропоиск
и удаление всех нейровекторов. При редактировании текста, отзыве Cloud-разрешения
или удалении воспоминания его вектор и связанные рёбра удаляются из активной БД.

### Ограничения

Семантическая близость — не доказательство истинности воспоминания.
AI не заменяет подтверждение пользователя, не исправляет автоматически противоречия
и не записывает произвольные слова пользователя в профиль. Передача фрагментов
последнего диалога в чат Cloud.ru регулируется отдельно от передачи памяти.
Нельзя гарантировать удаление уже отправленных провайдеру данных.
Удаление локальных нейровекторов не удаляет исходные сообщения и SQLite backup-файлы.
Желательно скопировать папку `data` при закрытом приложении перед обновлением.

Обновление на Windows CMD:
```bat
git pull origin main
npm ci
setup-python.cmd
```
После этого запустить `Meiyuren.cmd`.

## v0.10: восемь связанных мозгов памяти

К существующим пяти логическим областям (`identity`, `episodes`, `goals`,
`habits`, `knowledge`) добавлены ещё три:

- **Отношения** (`relationships`): только явно сохранённые сведения о связях с людьми; никаких самостоятельных выводов о третьих лицах.
- **Проекты** (`projects`): личные проекты, репозитории, разработка и продолжительные инициативы.
- **Решения** (`decisions`): явные решения и выбор, чтобы помнить принятый курс, а не только цели.

Итого **ровно восемь областей**, использующих один `MemoryEngine`, SQLite,
общий граф `shared_topic` и доступные по отдельному разрешению нейровекторы Cloud.ru.
Новых процессов, платных фоновых запросов или моделей на компьютере не добавлено.

Новые подтверждённые воспоминания получают область по осторожным локальным правилам.
Область можно изменить вручную. **Существующие факты v0.9 не переклассифицируются
автоматически**, чтобы не нарушить предыдущий ручной выбор; они продолжают
использоваться и могут связываться с новыми областями. Источники, ревизии,
сроки актуальности и ограничения приватности сохраняются.

Все восемь отображаются в «Настройки → Memory Core». Кнопка «Перестроить связи
восьми мозгов» пересоздаёт локальный тематический граф без Cloud.ru.
Нейросетевые embeddings остаются ручной, отдельно подтверждаемой и потенциально
платной операцией, как в v0.9. Граф отражает тематическое сходство, а не доказывает
истинность утверждений или наличие личных отношений.
