# Meiyuren v0.15 — Cortex Mesh: коллективная память восьми мозгов

Веб-аватар Meiyuren (React + TypeScript + Vite), левое SVG-меню, обновления GitHub и локальный сервер Python/FastAPI.

## Первый запуск на Windows (только CMD, без PowerShell)

После обновления Git-копии проекта:

```cmd
git pull origin main
npm ci
```

Дважды нажмите `setup-python.cmd`: скрипт создаст `backend/.venv` и установит FastAPI/Uvicorn (нужен Python 3.11+ и интернет для первой установки). Затем двойной щелчок по `Meiyuren.cmd` — Node найдёт свободные порты для сайта и Python, запустит оба сервера и откроет браузер.

Команды для обычной CMD вместо двойного щелчка:

```cmd
setup-python.cmd
npm run dev
```

На Linux/macOS:

```bash
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.txt
npm ci
npm run dev
```

При переносе папки на другой компьютер или носитель Python-окружение `backend/.venv` иногда нужно пересоздать. База `data/meiyuren.sqlite3` не включена в Git и остаётся с проектом.

## Чат

- История сообщений сохраняется в SQLite и отображается после перезапуска.
- Отправка сообщения записывает пару «вопрос/ответ» одной транзакцией.
- Окно показывает загрузку истории, состояние ответа и ошибки соединения.
- Очистка истории доступна из настроек после подтверждения.

## Память

В настройках → «Память Мэйюрэн» можно вручную записать и сохранить заметку (не более 4000 символов). Она остаётся в SQLite, даже если приложение закрыто. Для проверки отправьте в чат «Что ты помнишь?».

**По умолчанию:** демонстрационный локальный бот. Для настоящей облачной модели настройте Cloud.ru в боковом меню (значок облака).

## API

- `GET /api/health` — статус Python.
- `GET /api/chat/messages?limit=200` — последние сообщения.
- `POST /api/chat/messages` — сообщение и ответ.
- `DELETE /api/chat/messages` — удаление истории.
- `GET /api/memory` — чтение заметки.
- `PUT /api/memory` — сохранение заметки.

Python слушает только `127.0.0.1`, порт 8000–8099. Веб-адрес — свободный порт 5173–5272. Vite направляет запросы чата на фактический порт Python.

## Cloud.ru Foundation Models (v0.5)

В левом меню появилась новая **векторная иконка облака без подписи** (подсказка при наведении). После клика откроется окно настроек Cloud.ru.

1. Создайте сервисный API-ключ в [консоли Cloud.ru](https://cloud.ru/docs/foundation-models/ug/topics/quickstart) для сервиса Foundation Models.
2. Введите **Key Secret** в поле с маскировкой и нажмите **Сохранить ключ**.
3. Нажмите **Получить список** — сервер проверит подключение через `GET /v1/models`.
4. Выберите текстовую модель и нажмите **Применить модель**. С этого момента чат использует `POST /v1/chat/completions`.
5. Кнопка **Выключить Cloud.ru** возвращает демонстрационный локальный режим. **Удалить** удаляет ключ из системного хранилища.

**Ключ не хранится в браузере, SQLite, Git или файлах конфигурации.** Backend использует библиотеку `keyring` и системное хранилище секретов, например Windows Credential Manager. На ОС без доступного безопасного хранилища сохранение будет запрещено. Секрет никогда не возвращается в ответы API.

Выбранная модель и переключатель облачного режима хранятся в SQLite (`cloud_settings`). Cloud.ru получает **текущий текст, до 12 сообщений истории и содержимое заметки памяти** только при включённом облачном режиме. Запросы могут быть платными, интернет обязателен. Статус ключа доступен без раскрытия его значения.

При обновлении проекта запустите `setup-python.cmd`, чтобы установить новые зависимости Python (`httpx` и `keyring`). Окружение нельзя без проверки переносить между Windows-компьютерами. Повторный вход ключа может потребоваться после переноса на другой ноутбук.

Подробная инструкция: [docs/cloud-ru.md](docs/cloud-ru.md).

## Новое в v0.6: диагностика, поток, память

- **Cloud.ru → Проверить соединение:** проверка ключа и списка моделей через GET /v1/models, без генерации и без расходов на чат. Это не подтверждение работоспособности всех параметров выбранной модели.
- **Cloud.ru → Тест ответа (платно):** после явного подтверждения выполняется короткий реальный запрос; результат записывается в основной чат.
- **Чат:** сообщения Cloud.ru приходят по частям (SSE), доступны остановка ответа, выбор диалога, создание и переименование, удаление второго диалога, поиск по сообщениям.
- **Память:** список фактов, которые пользователь добавляет и удаляет вручную. Существующая заметка остаётся. В облачном режиме ограниченная часть фактов и заметки отправляется Cloud.ru.
- **SQLite:** старые сообщения автоматически закрепляются за «Основным диалогом», новая таблица `conversations`, `memory_facts`, столбец `conversation_id` в `messages` и `cloud_requests`. Изменения мигрируются при запуске.
- **Отмена:** клиент может остановить поток; это не означает, что Cloud.ru не обработал часть запроса или что деньги не списаны. Идентификатор запроса продолжает предотвращать автоматический повтор.

### Потоковое API

`POST /api/chat/stream` — локальный SSE-поток с событиями `delta` (часть текста), `done` (сохранённый обмен), `error`. Поток сохраняется в SQLite только по успешному завершению генерации. Запросы Cloud.ru помечаются `unknown` при прерывании, чтобы повтор с тем же идентификатором не вызвал новый платный запрос.

### Важно при обновлении

**Перед первым запуском новой версии сделайте резервную копию папки `data/`**. Обновление схемы SQLite — изменение данных; откат кода через Git не откатывает структуру базы. Старые сообщения остаются доступными через основной диалог.

Для Windows CMD: `git pull origin main`, `npm ci`, `setup-python.cmd`, `Meiyuren.cmd`.

## Memory Core v0.7: одна локальная система памяти

- Один модуль Python: `backend/app/memory_engine.py` с SQLite, без Ollama, Redis, дополнительного сервиса и дополнительных Cloud.ru вызовов.
- Перед ответом Мэйюрэн ищет актуальные воспоминания через SQLite FTS5 и ограничивает их контекстом. Для Cloud.ru **по умолчанию** передача заметки и фактов запрещена; в настройках нужно явно разрешить категории и конкретный факт.
- После успешного ответа локальная очередь создаёт предложения на сохранение важных фактов (например, «Запомни: ...» и простые предпочтения), а длинным диалогам предлагает **черновики дословных выписок**. Ничего из этого не считается проверенным до подтверждения пользователем.
- Настройки → Память: подтверждение/отклонение кандидатов, редактирование фактов с защитой от конфликтов, источник воспоминания, разрешение передачи Cloud.ru и удаление.
- Для старых фактов отсутствует достоверный источник: они импортируются с меткой `legacy`, без передачи в Cloud.ru.
- Забывание удаляет запись из активного индекса FTS5, старой таблицы, кандидатов и связанных сводок. Оно **не стирает** исходный текст из отдельных сообщений истории и существующих резервных копий.
- Сводки локальные и дословные; НЕ генерируются и НЕ исправляются AI. Автоматического разрешения их отправки в Cloud.ru нет.
- В фоне — только локальная обработка. Никаких автоматических платных запросов Cloud.ru, в том числе после сбоя.

### Перед обновлением

Перед первым запуском v0.7 сделайте дополнительную резервную копию папки `data` при выключенном приложении. При миграции существующей базы Memory Core создаст файл `data/meiyuren.sqlite3.before-memory-core.bak` (однократно, если такого файла нет). Используются резервное копирование SQLite и транзакции.

На Windows только CMD: `git pull origin main`, `npm ci`, `setup-python.cmd`, затем `Meiyuren.cmd`.

### Ограничения

- Локальное извлечение кандидатов использует консервативные правила, а FTS5 — лексический поиск без полноценной русской семантики. Сложные противоречия не разрешаются автоматически, факты не переписываются по предположениям AI.
- Разрешение на передачу памяти **не** запрещает передавать в Cloud.ru последние сообщения активного диалога, если включён облачный чат. Не вводите секреты в облачный чат.
- Локальные резервные копии и прежние Cloud.ru-запросы не отзываются при удалении записи памяти.
- Без отдельного подключения Cloud.ru не проверяется работа с реальным ключом или фактическая тарификация.

## v0.8: надёжность и объяснимость памяти

- **Гонка с Cloud.ru:** очистка истории увеличивает generation диалога в той же SQLite-транзакции. Уже выполняющийся запрос, начатый до очистки, не может снова записать старое сообщение; при неопределённости повтор платного запроса не выполняется.
- **Забывание и сводки:** локальная сводка теперь включает **только подтверждённые и актуальные факты с существующим сообщением-источником**. Сырые реплики не копируются автоматически. Удаление факта удаляет производную сводку, исключает исходный ID и запрещает автоматически переизвлекать его.
- **Очередь:** сводка планируется только после каждых шести обменов (12 сообщений), задания завершённые/ошибочные удаляются из журнала через 7 дней, а выполняемые задания восстанавливаются по lease с ограничением трёх попыток. Отдельных платных Cloud-запросов нет.
- **Версии:** редактирование и подтверждение записываются в локальный журнал ревизий. После удаления факта журнал его содержимого тоже удаляется.
- **Противоречия:** простые противоположные высказывания о предпочтении по одной теме предлагаются на рассмотрение. При подтверждении старое утверждение получает статус superseded и исключается из поиска; сложные противоречия не распознаются автоматически.
- **Поиск:** FTS5 с консервативным усечением типичных русских окончаний, фильтрацией устаревших и запрещённых записей, выводом списка выбранных фактов. Это не семантический поиск.
- **Прозрачность:** в настройках Memory Core можно увидеть происхождение и ревизии факта, срок актуальности, предпросмотр контекста для Cloud.ru и журнал фактов, выбранных при подготовке ответа. Предпросмотр не вызывает генерацию Cloud.ru.
- **Backup:** файл `data/meiyuren.sqlite3.before-memory-core.bak` сохраняется консистентным SQLite-снимком **до** миграции, если файл ещё не существует. Перед обновлением всё равно стоит скопировать всю папку `data` при выключенном приложении.

**Ограничения:** удаление памяти не стирает текст исходных пользовательских сообщений, уже отправленные в Cloud.ru данные или резервные копии; для удаления истории используйте управление диалогами. Журнал выбора памяти означает включение в подготовленный контекст, а не подтверждённый ответ провайдера. Фоновые задачи локальные; Ollama не требуется. Для обновления используйте Windows CMD, не PowerShell.

## v0.9: пять связанных «мозгов» детальной долговременной памяти

Это **пять логических областей одной локальной базы**, а не пять отдельных LLM-процессов:
личность (`identity`), события (`episodes`), цели (`goals`), привычки (`habits`),
знания (`knowledge`). Новые факты распределяются консервативными локальными правилами,
но область можно изменить вручную. Старые факты сохраняются и получают категорию
при миграции (без выдумывания новых сведений). SQLite остаётся единственным хранилищем.

**Нейросвязи** двух видов:

- `shared_topic`: локальный граф связей по пересечению ключевых слов, бесплатно и без сети.
  Одношаговый переход по связям может добавить релевантные факты к FTS5-результатам,
  но не отменяет правила разрешений, области диалога и сроков актуальности.
- `neural_similarity`: настоящие семантические связи по косинусной близости векторов
  embedding-модели `Qwen/Qwen3-Embedding-0.6B` (1024 компоненты).
  Генерация каждого вектора **только вручную**, после разрешения пользователя и
  отдельного подтверждения потенциально платного вызова Cloud.ru.

### Правила приватности и стоимости

По умолчанию `allow_cloud_embeddings=false`. Чтобы индексировать факт нейросетью,
нужно отдельно разрешить embeddings в настройках и разрешить Cloud.ru
**конкретному факту**. Поиск по смыслу тоже требует отдельного подтверждения
и потенциально оплачиваемого API-вызова `POST /v1/embeddings`.
**Никаких фоновых embedding-запросов**, автоматических повторов, Ollama,
Redis или отдельной БД. При сбое результат запроса сохраняется как `unknown`,
повтор того же requestId отклоняется. Ни содержание ключа, ни полные векторы не
возвращаются через API Meiyuren. Нейровекторы и граф хранятся в SQLite.

В настройках памяти доступны распределение по пяти областям, ручное назначение
области факта, просмотр связей, создание вектора, ручной нейропоиск
и удаление всех нейровекторов. При редактировании текста, отзыве Cloud-разрешения
или удалении воспоминания его вектор и связанные рёбра удаляются из активной БД.

### Ограничения

Семантическая близость — не доказательство истинности воспоминания.
AI не заменяет подтверждение пользователя, не исправляет автоматически противоречия
и не записывает произвольные слова пользователя в профиль. Передача фрагментов
последнего диалога в чат Cloud.ru регулируется отдельно от передачи памяти.
Нельзя гарантировать удаление уже отправленных провайдеру данных.
Удаление локальных нейровекторов не удаляет исходные сообщения и SQLite backup-файлы.
Желательно скопировать папку `data` при закрытом приложении перед обновлением.

Обновление на Windows CMD:
```bat
git pull origin main
npm ci
setup-python.cmd
```
После этого запустить `Meiyuren.cmd`.

## v0.10: восемь связанных мозгов памяти

К существующим пяти логическим областям (`identity`, `episodes`, `goals`,
`habits`, `knowledge`) добавлены ещё три:

- **Отношения** (`relationships`): только явно сохранённые сведения о связях с людьми; никаких самостоятельных выводов о третьих лицах.
- **Проекты** (`projects`): личные проекты, репозитории, разработка и продолжительные инициативы.
- **Решения** (`decisions`): явные решения и выбор, чтобы помнить принятый курс, а не только цели.

Итого **ровно восемь областей**, использующих один `MemoryEngine`, SQLite,
общий граф `shared_topic` и доступные по отдельному разрешению нейровекторы Cloud.ru.
Новых процессов, платных фоновых запросов или моделей на компьютере не добавлено.

Новые подтверждённые воспоминания получают область по осторожным локальным правилам.
Область можно изменить вручную. **Существующие факты v0.9 не переклассифицируются
автоматически**, чтобы не нарушить предыдущий ручной выбор; они продолжают
использоваться и могут связываться с новыми областями. Источники, ревизии,
сроки актуальности и ограничения приватности сохраняются.

Все восемь отображаются в «Настройки → Memory Core». Кнопка «Перестроить связи
восьми мозгов» пересоздаёт локальный тематический граф без Cloud.ru.
Нейросетевые embeddings остаются ручной, отдельно подтверждаемой и потенциально
платной операцией, как в v0.9. Граф отражает тематическое сходство, а не доказывает
истинность утверждений или наличие личных отношений.

## v0.11: Autonomous Memory Growth

**Восемь постоянных мозгов теперь самостоятельно выращивают вложенные ветви** из
повторяющихся тем подтверждённых воспоминаний. Категории тем не фиксируются:
Python, FastAPI, музыка, игры, проекты и другие направления формируются из
фактически сохранённой информации. Каждый узел хранит число подтверждающих
воспоминаний, родительский узел, корневой мозг и связи с исходными фактами.
Подтверждение новым человеком не подразумевается: повторная тема должна
появиться минимум в **двух различных сохранённых утверждениях**.

### Полностью локальный автоматический цикл

- Чат сохраняет обмен как прежде, фоновой Python-worker обрабатывает новую
  реплику. Прямые, однозначные и не похожие на чувствительные высказывания
  сохраняются **автоматически** как `kind=auto` с источником, версией и
  `cloud_allowed=false`. При режиме `auto_growth=true` предложений на
  подтверждение нет. Эвристический фильтр может пропустить полезный факт
  или ошибочно принять формулировку; сохранённое всегда можно исправить
  или удалить.
- Простые явные изменения противоположных предпочтений заменяют предыдущую
  актуальную версию автоматически; история редакций сохраняется до удаления.
  Сложные противоречия НЕ разрешаются без оснований.
- После принятия факта перестраиваются связи и вложенные темы.
  Дерево имеет 8 постоянных корней, до 4 уровней новых ветвей, до 8
  дочерних ветвей на узел и 320 новых узлов в одном цикле.
  За один проход рассматривается до 500 последних подтверждённых фактов.
  Это гарантирует ограниченную нагрузку, **не бесконечную ёмкость**.
- Локальные выписки диалогов из подтверждённых фактов с живыми источниками
  автоматически отмечаются как разрешённые для **локального** использования,
  но не для Cloud.ru.
- Локальное обслуживание раз в 30 минут очищает неактуальные векторы,
  связи и пересчитывает ветви. При старте приложение восстанавливает
  дерево из существующих воспоминаний. При удалении факта ветви перестраиваются,
  чтобы память не оживляла отозванную информацию.

Все функции находятся в существующем **`backend/app/memory_engine.py`**;
используются FastAPI и SQLite. Никаких фоновых сетевых обращений, отдельной
LLM или незаметных платных запросов не добавлено. Семантические Cloud.ru
embeddings из v0.9 по-прежнему требуют разрешения и ручного действия.

### Настройки

`Настройки → Memory Core` показывает дерево направлений, число фактов в
каждой ветви и количество автоматически выращенных ветвей.
`auto_growth` включён по умолчанию; его можно отключить. При выключении
новые факты снова попадают в прежнюю очередь подтверждения.
Текущее автосохранение запускается, только если также включён `auto_extract`.

**Безопасность и ограничения:** локальная эвристика не является доказательством
истины, проверка секретов не гарантирует отсутствие всех чувствительных данных.
Автоматический рост графа не означает переобучение весов нейросети,
генерацию нового программного кода или автономный интернет-поиск.
Мэйюрэн сама не получает право запускать действия в сторонних системах.
В активном Cloud.ru-чате содержание текущих сообщений может передаваться
провайдеру по прежним правилам.

## v0.12 — Eight-Brain Deep Memory

Восемь мозгов используют общий проверяемый журнал фактов и **координатор поиска**.
Новый `MemoryEngine.deep_recall()` объединяет лексический поиск, тематические ветви,
незавершённые проекты, цели и принятые решения, при необходимости выполняет
до двух переходов по существующим тематическим/нейронным рёбрам.
Результаты ограничены 8 записями по умолчанию; в облачный контекст попадают
только разрешённые записи, укладывающиеся в бюджет. Платных запросов для
этого не создаётся.

- **Хронология:** сохранённые подтверждённые воспоминания с исходным ID и
  временем наблюдения (когда факт записан), но это не обязательно дата самого события.
- **Проекты и цели:** активен / завершён / отложен / неизвестно определяется только
  по явным формулировкам; система не выдумывает прогресс или завершение.
- **Решения:** показывает источник и причину **только если она прямо указана**
  (например, «потому что»). Это запись утверждения пользователя, не доказательство причинности.
- **Память продолжения:** фразы вроде «продолжим там, где остановились»
  вызывают поиск актуальных проектов, целей и решений без ручной навигации по 8 мозгам.
- **Многоуровневые представления:** краткий обзор (3 факта на мозг) и подробный
  (до 16); всегда собираются из актуальных разрешённых фактов,
  отдельные непроверенные копии текста не создаются.
- **Локальная консолидация:** индексы событий, метаданные состояний и карты ID
  обновляются после изменений памяти и при периодическом обслуживании.
  Удалённые/истёкшие факты не возвращаются из этих представлений.
- **Обратная связь:** «Полезно»/«Не по теме» увеличивает/уменьшает
  приоритет поиска; достоверность утверждения остаётся прежней.
- **Метрики:** количество локальных поисков по категориям и доля поиска
  с хотя бы одним кандидатом. Это **метрика покрытия**, а не точности ответа.
  Полные тексты запросов не записываются в аналитические таблицы.
- **Нагрузочная регрессия:** контрольный SQLite-фикстурный тест на 320 фактах;
  это проверка отсутствия серьёзной деградации, не обещание скорости
  на миллионах сообщений.

В `Настройки → Memory Core` доступна глубокая хронология, направления
продолжения, причины решений, развёрнутые обзоры и отметки релевантности.
API: `/api/memory/deep/overview`, `/api/memory/deep/metrics`,
`/api/memory/deep/rebuild`, `/api/memory/deep/facts/{id}/feedback`.
Реальные платные embeddings Cloud.ru остаются **только вручную**, с
согласием на конкретный факт и потенциальную оплату.

## v0.13 — Deep Episodic Memory & Continuous Context

К v0.12 добавлены **эпизоды переписки** и **контрольные точки проектов**, не меняя
число исходных восьми мозгов, Python-модуль `memory_engine.py` или SQLite.

- **Эпизод:** группирует действующие подтверждённые факты одного диалога
  по дате *получения исходного сообщения* в UTC, с сохранением источников.
  Изолированные пользовательские заметки без исходного сообщения не
  притворяются эпизодами чата. Каждый эпизод имеет короткую выписку из
  максимум трёх фактов и подробное раскрытие до 24 фактов.
- **Время события:** если пользователь прямо указал абсолютную дату
  `YYYY-MM-DD` или `DD.MM.YYYY`, она выделяется отдельно. В остальных
  случаях дата события считается **неизвестной**, а время записи не
  выдаётся за дату совершения события. Относительные выражения вроде
  «вчера» намеренно не преобразуются без достоверной временной зоны.
- **Проектные контрольные точки:** явные названия проектов связываются
  с фактическими утверждениями «начал / работаю / отложил / завершил».
  Только последняя контрольная точка определяет отображаемое состояние;
  завершённый проект не восстанавливается как активный по старому факту.
  Без названия проекты не объединяются по предположению.
- **Продолжение работы:** поиск фраз «продолжим» и «где остановились»
  использует последние подходящие контрольные точки. Компилятор
  контекста сохраняет бюджет символов и прежние проверки ACL.
- **Многоуровневая память:** короткий/полный обзор существующих фактов и
  связей v0.12 дополнен эпизодами и контрольными точками. Производные
  таблицы хранят ID, состояния и временные метки, **не новые копии
  текста переписки**. Детали собираются из живых источников при чтении.
- **Автоматическая консолидация:** индексы эпизодов и контрольных точек
  перестраиваются вместе с Deep Memory при изменении/удалении памяти и
  периодическом обслуживании. Снимок заменяется атомарной SQLite-транзакцией.
- **Испытание длинной истории:** CI проверяет SQLite с 10 000 синтетических
  сообщений и 1 200 подтверждённых фактов, а также удаление, перезапуск,
  время события, границы диалогов и права Cloud.ru.

Новые API: `GET /api/memory/episodes` и
`POST /api/memory/episodes/rebuild`. UI: **Настройки → Memory Core →
Эпизодическая память**. Сеть, отдельные платные LLM-вызовы,
автоматическое создание Cloud.ru embeddings и новые сервисы **не добавляются**.

Ограничения: эвристики не извлекают сложные события автоматически из любого
произвольного текста; эпизоды основаны на фактически подтверждённых
воспоминаниях, а не на всей переписке. Группировка происходит по календарному
дню UTC; подлинные причинно-следственные отношения не выводятся.
Список для индексации ограничен последними 2000 фактами,
и раскрытие каждого эпизода — 24 фактами; это контролируемые пределы
ресурсов, а не заявка на бесконечное хранение. Полная история чатов
остаётся в SQLite отдельно от индексированных воспоминаний.

## v0.14 — Autonomous Eight-Brain Neuroevolution

**Автономный локальный режим** развивает всё уже реализованное в v0.7–v0.13:
долговременные подтверждённые факты, 8 корневых мозгов, тематические ветви,
связи между воспоминаниями, эпизоды, контрольные точки проектов, контекст
продолжения, индексы, локальные сводки и периодическую очистку.

Новые механизмы, реализованные внутри того же `backend/app/memory_engine.py`:

- **Микромозги:** зрелые вложенные области глубиной >=2, поддержанные
  как минимум тремя действующими фактами, автоматически становятся
  специализациями. Это лёгкие SQLite-проекции, а не новые модели.
  Максимум 96 одновременно активных; при изменении/забывании память
  пересчитывается, сиротские специализации не остаются.
- **Нейропластичность:** оценки «Полезно / Не по теме» меняют локальный вес
  рёбер графа на ±0.04, ограничено диапазоном ±0.4.
  Использование воспоминания в ответе **не считается доказательством**
  его истинности. Удаление и редактирование уничтожает относящиеся
  к старому содержимому адаптивные связи.
- **Поколения поиска:** ограниченный локальный тест сравнивает
  `balanced`, `focused`, `context`. Допуск новой стратегии возможен
  лишь при наличии 12+ испытаний и преимуществе >=0.05 относительно
  текущей стратегии. Нет автоматической генерации/исполнения кода,
  изменений модели, скрытого сетевого обучения или выдуманных фактов.
- **Метрика:** локальный тест на самовосстановление факта по ключевым
  словам — **синтетический proxy**, не измерение правильности
  ответов в реальном диалоге. При равных результатах и недостатке
  доказательств активная стратегия сохраняется. Данные истории
  эволюции не включают исходные сообщения; храним максимум 40
  поколений и небольшие агрегаты.
- **Автоматика:** локальный обработчик памяти запускается вместе с
  приложением и каждые 30 минут оценивает возможность эволюции
  (без Cloud.ru). Извлечение фактов и рост уже существовали в v0.11,
  эпизоды и контрольные точки — в v0.13. Для автономного режима
  `auto_evolution=true` по умолчанию, отключается в расширенных
  настройках. Ни один процесс не запускается после закрытия приложения.
- **Управление ресурсами:** до 120 фактов на один эволюционный прогон,
  до 80 синтетических кейсов, три проверяемые стратегии, не более
  одного штатного прогона за 30 минут; без Ollama, Redis и фоновых
  API-вызовов. Для ручного восстановления доступен безопасный откат
  к стратегии `balanced`.

## v0.15 — Cortex Mesh: проверяемая коллективная память

Восемь корневых мозгов, логические микромозги v0.14 и весь Memory Core остаются
в **одном Python \`backend/app/memory_engine.py\` и SQLite**. Реализовано:

- **Динамические межмозговые связи** \`memory_cortex_edges\`: между
  двумя различными мозгами, на основании минимум **двух общих лексических
  признаков в подтверждённых действующих фактах**. Каждая связь опирается
  на два исходных ID, не создаёт новых пользовательских фактов и
  **не является доказательством истины или причинности**.
  Два разных приватных диалога не соединяются друг с другом; глобальные
  подтверждённые факты могут связываться с фактами диалога. При чтении
  всегда заново проверяются права, актуальность и Cloud-разрешения обоих
  источников.
- **Коллективный поиск**: координатор v0.12–v0.14 может дополнить
  релевантные воспоминания из других мозгов двумя подтверждёнными
  межмозговыми переходами, сохраняя слоты для прямых совпадений и не
  превышая существующий бюджет контекста. Сохраняется возможность
  объяснить каждую связь через оба исходных воспоминания.
- **Локальная метапамять и прозрачность источников**: число доступных
  подтверждённых фактов, записей с источником сообщения, без источника
  сообщения и возможных конфликтов явно выраженных предпочтений.
  Отсутствие источника сообщения не означает ложность вручную
  подтверждённого факта; противоречия лишь сигнализируются.
- **Контроль качества**: детерминированная локальная сравнительная
  проверка baseline и Cortex Mesh на до 32 синтетических кейсах из
  действующих фактов. Два счётчика попаданий оценивают восстановление
  **известного источника**, а не правильность реальных ответов.
  Эти данные не используются для объявления автоматического роста
  интеллекта и не подменяют внешние независимые тесты.
- **Автоматическая консолидация**: межмозговой граф перестраивается
  с прочими индексами при сохранении/редактировании/забывании, после
  запуска и в локальном обслуживании работающего приложения. Граф
  пересобирается атомарной SQLite-транзакцией; удалённые, superseded
  и истёкшие факты исключаются. Адаптивные веса старых связей
  очищаются при редактировании/забывании, а новые связи получают
  обратную связь только по явной оценке пользователя.
- **Защита ресурсов**: до 500 последних подтверждённых фактов в
  одном построении, до 8 межмозговых связей на факт, до 900 рёбер
  суммарно; слишком общие темы не создают огромных клик.
  Проходы автоматически запускаются в работающем приложении,
  без отдельного сервиса, Ollama, Redis или фоновых платных запросов.

**Интерфейс:** после настройки Cloud.ru по-прежнему открывается чат.
В «Настройки → Memory Core» показаны число межмозговых связей и
связанных мозгов; в расширенных настройках — происхождение данных,
возможные противоречия, результаты контрольного теста и возможность
повторить его локально без платного AI.

**API:** \`GET /api/memory/cortex\`,
\`GET /api/memory/cortex/facts/{fact_id}/connections\`,
\`POST /api/memory/cortex/rebuild\`,
\`POST /api/memory/cortex/evaluate\`.

**Ограничения:** лексическое совпадение двух слов может создать
ошибочную тематическую связь; текущая проверка является синтетической,
а не независимой разметкой человеком. Реальная точность требует
отдельных испытаний на длительных разговорах. Никакие веса LLM не
переобучаются. Автоматического доступа к Интернету, платного
Cloud.ru, изменения собственного кода и создания независимых
нейросетей не добавлено. Все предыдущие пользовательские подтверждённые
факты и правила забывания сохраняются.
